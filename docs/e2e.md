# 真实 Channel 验证

`npm run check` 使用真实 Plugin Worker 和模拟 Harness Adapter。以下验收通过已部署服务、网页 Channel 和真实 Codex 执行，不计入该自动测试结果。测试限定在独立开发实例和测试工作目录；记录 `/health` 的 revision、测试会话名、时间、Work id、状态与回复，证据放在工作区测试产物目录中，不提交登录态或完整私人会话。

前提：服务正常运行，Codex 已登录，网页能够连接。Hooks 信任与工具权限按网页显示的具体请求由用户决定；请求超时算阻塞或失败，不算通过。识别失败可原消息编号重试。运行前在服务的工作目录中准备只含测试数据的文件，验收完成后暂停测试安排。

## 临时交办

在测试文件中写入一个随机标记，不把标记放入提示词。通过网页交办“读取这个文件并告诉我验证标记，不修改文件”。

验收：识别产生一个 Task；状态最终为 done；回复含文件中的准确标记；Harness 执行记录包含实际读取文件。刷新网页后仍能看到同一事项和回复。HTTP 接收成功或单独出现 done 均不足以判定通过。

## 进度说明与最终结果

交办一个只读文件检查任务，要求先简短说明准备做什么，再调用工具读取文件，最后给出结构化结果。记录原生 Harness 中分别标记为 `commentary` 和 `final_answer` 的消息。

验收：查询命令成功，最终 JSON 独立进入 Turn 的 `finalText`，进度文字仍保留在 `agentText`；事项为 done，回复包含真实读取结果。不能仅用“不输出进度说明”的请求绕开此场景。

## 追问与恢复

交办“创建一次性事项：替我写一段欢迎语，先问我希望使用的称呼，收到回答后再完成，不调用外部系统”。

验收：产生 Task，执行后为 waiting，问题可见；在 waiting 状态重启开发服务并刷新网页，问题仍在。回答一个唯一称呼，确认沿用同一个 Work id，最终为 done，欢迎语使用这个称呼。核对没有新建重复事项。

## 定期处理

交办“每分钟检查指定测试文件。首次只记录基线，有变化时告诉我变化后的标记，没变化时不要通知，不修改文件”。

验收：产生 Routine 并有 nextAt；首次执行后仍为 scheduled。关闭页面，在测试目录修改标记，等待下个触发后重新打开页面，确认收到正确变化通知。同一内容再触发一轮不重复通知。发送暂停请求，确认为 paused 且 nextAt 为空；越过下个周期后执行次数不增加。恢复后仍使用原 Work id；验证完成后再次暂停。

将每一项记为通过、失败或阻塞，并注明实际覆盖的步骤。缺失权限决定、模型连接失败、页面未执行或未等待周期，都不能用模拟测试结果替代。
